# Task 2 — Observation

## 예상과 실제 결과

beta가 높아지면 더 많은 반복이 필요하고, 그래프 크기는 반복 횟수보다 한 번의 반복 비용에 크게 영향을 줄 것으로 예상했다. 같은 고정 시드 생성기와 균등 초기값을 사용하고 조건별로 3회 실행했다. CPU는 Core i5-11400H, RAM 약 15.74 GiB, Python 3.11.9이며 Codex 외 앱 부하는 통제하지 않았다.

1,200개 그래프에서 beta=0.5·0.7·0.85·0.95·0.99의 수렴 횟수는 14·17·20·23·24회였다. beta가 커지면 순간 이동이 줄어 링크 구조의 영향이 더 오래 남고 L1 수축 보장도 약해진다. 다만 이번 그래프는 0.99에서도 24회에 수렴했으므로 급격한 지연을 관찰했다고 과장하지 않는다.

## 반복 횟수와 시간은 다르다

노드 수를 1,200에서 6,000으로 5배 늘렸을 때 반복 횟수는 14·18·22·24·25회로, 같거나 1–2회만 늘었다. 반면 시간은 더 크게 증가했다. 더 많은 노드와 간선을 매번 처리하기 때문이다. 생성 방식은 같지만 링크 구조까지 동일하지는 않으므로 크기만의 효과로 단정하지 않는다. 실행 시간이 짧고 환경 변동도 있어 중앙값과 범위를 함께 기록했다.

beta=0.85에서 tol을 1e-3부터 1e-7까지 한 자리씩 엄격하게 하자 반복 수는 7·9·10·12·14회였다. 한 자리당 1–2회, 전체 평균 1.75회가 추가됐다. 이 수치는 이번 조건의 결과이며 보편적인 상수는 아니다.

## 상위 집단은 같아도 순서는 달라졌다

두 그래프 크기 모두 상위 10개 구성은 같았지만, 측정한 beta 중 0.7에서 처음으로 p00000과 p00004의 7·8위가 뒤집혔다. 0.5와 0.7 사이의 정확한 역전점은 측정하지 않았다. 1,200개 그래프의 점수 차이는 약 0.000606에서 반대 방향의 약 0.003871로 바뀌었으며 계산 종료 오차보다 크다. 따라서 순위 발표 시 beta를 명시하고 세부 순위가 설정에 민감할 수 있음을 고려해야 한다.
