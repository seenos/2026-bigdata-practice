# Week 6 — Observation

## Task 1

지지도 50의 생성 데이터에서 1468→0의 신뢰도는 83.87%, 반대 방향은 약 0.398%였다. 전자의 조건부 비율이 높지만 항목 0 자체가 65.4%의 장바구니에 있어 향상도는 약 1.282이며, 별도 검증 없이 강한 관계나 인과관계로 해석하지 않는다.
상품 2,000개의 가능한 쌍은 1,999,000개이고, 첫 통과 후 1,849개 항목의 가능한 쌍은 1,708,476개다. 실제 함께 등장해 생성한 카운터는 820,259개, 최종 빈발 쌍은 6,397개로 후보 공간·계수 대상·정답 수를 구분해야 한다.
공식 5개 검증과 작은 무작위 데이터 40개의 전수 비교를 통과했다. [상세 관찰](../observations/task1.md)

## Task 2

지지도 400→200→100→50에서 카운터는 약 5.54·4.67·3.00배 증가했지만, 모든 항목이 살아남은 뒤에는 후보 수가 포화됐다. 반면 낮은 지지도에서 정답 수는 계속 늘었고 지지도 1에서는 모든 계수 대상이 정답이 됐다.
기본 20,000개 입력은 지지도 1에서도 기준에 미달했다. 장바구니 200,000개 보충 실험에서 지지도 250 실행을 60.69초·관측 최고 추가 할당 204.88 MB에서 시간 기준으로 중단했다. 이는 시간·메모리 고갈이 아닌 사전에 정한 대기·할당 예산의 중단이며 원래 데이터와 구분한다.
카운터 수·최종 정답 수·반환 결과를 포함한 Python 메모리는 서로 다른 지표다. [상세 관찰](../observations/task2.md) · [측정 표·그래프](explosion.md) · [A2 보충 근거](a2_boundary.md)

## Task 3

1,048,576개 버킷을 사용하고 첫 통과 뒤 정수 배열을 비트맵으로 바꿔 해제했다. 동일한 빈발 쌍 6,397개를 찾았으며 출력 사전까지 보수적으로 센 최대 쌍 카운터는 19,518개로 97.6% 감소했다.
버킷 배열 약 4 MiB까지 포함한 추가 Python 할당에서 1,000개는 PCY가 불리했고 5,000개는 유리했다. 이는 고정 support=50과 입력 분포에 한정된 관찰이다.
버킷을 16,384개로 줄이면 충돌로 후보가 늘었다. 카운터 점수와 전체 추가 메모리·속도를 구분해야 한다. [상세 관찰](../observations/task3.md) · [공식 결과](bench.txt)
