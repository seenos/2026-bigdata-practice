# Task 2 — A2 추가 한계 탐색

## A2 보충 실험 — 입력을 늘린 뒤 지지도 낮추기

기본 20,000개 입력은 지지도 1에서도 부담 기준에 도달하지 않았다. 양의 등장 횟수 기준을 더 낮출 수 없어 같은 생성기의 장바구니 수를 200,000개로 늘렸다. 상품 2,000개, 평균 길이 20, seed=246과 PlainApriori 알고리즘은 유지했다. bench.py 파일은 바꾸지 않고 별도 프로세스에서 BASKETS 값만 설정했다.

기본 실험의 곡선과 다른 데이터이므로 결과를 explosion.json의 같은 표에 섞지 않았다. 큰 입력 하나를 고정하고 지지도를 순서대로 낮췄다. 앞선 20만 개 실행의 지지도 4,000·2,000·1,000·500은 완료했으나 250 실행이 감시 타임아웃으로 중단되어 마지막 알고리즘 표본은 약 52초였다. 이 값만으로 60초에 도달했다고 주장하지 않고, 250부터 별도로 이어서 확인했다. [앞선 실행 원자료](evidence/a2_boundary_200000_interrupted.json)는 보존한다.

앞서 100,000개 입력에서는 지지도 2,000부터 1까지 완료했고 최대 39.35초·624.91 MB로 기준에 미달했다. [이 확장 단계의 원자료](evidence/a2_boundary_100000.json)도 보존한다.



사전에 정한 종료 기준은 알고리즘 대기 60초 또는 추가 Python 할당 1.0 GB다. 별도 감시 프로세스가 약 1초 간격의 측정값을 받아 해당 실행을 중단했다. 시간은 tracemalloc과 진행 감시의 오버헤드를 포함하고 입력 생성은 제외한다. 메모리는 미리 생성한 입력을 제외한 추가 Python 할당으로 전체 프로세스 RAM이 아니다.

| 지지도 | 상태 | 알고리즘 시간(s) | 관측 최고 추가 할당(MB) | 쌍 카운터(중단 행은 부분값) | 최종 빈발 쌍 |
|---:|---|---:|---:|---:|---:|
| 4000 | 완료 | 15.02 | 1.26 | 10,011 | 252 |
| 2000 | 완료 | 25.04 | 6.57 | 57,970 | 766 |
| 1000 | 완료 | 37.97 | 29.90 | 323,543 | 2,198 |
| 500 | 완료 | 53.56 | 204.40 | 1,720,177 | 6,176 |
| 250 | 기준 도달로 중단 | 60.69 | 204.88 | 1,706,593 | 미완료 |

장바구니 200,000개 보충 실험에서 지지도 250 실행을 60.69초·관측 최고 추가 할당 204.88 MB에서 시간 기준으로 중단했다. 중단된 행은 마지막 실시간 표본이므로 최종 실행 시간·최종 카운터 최고값·정답 수가 아니다. 정답 수나 중단 이후 결과를 추정해 채우지 않았다.

중단 행의 카운터가 직전 완료 행보다 작은 것은 아직 입력 전체를 처리하지 않았기 때문이다. 이 두 수로 지지도 하락에 따른 최종 카운터 증가율을 계산하지 않는다. 표의 완료 행과 중단 행은 서로 다른 실행 묶음이며 시간 차이를 지지도만의 효과로 단정하지 않는다.

직전 완료 지지도는 500이다. 이는 측정한 단계에서 처음 종료 예산을 넘긴 지점이며 그 사이의 정확한 교차점, 사용자의 주관적인 불편함, 메모리 부족, 기계의 물리적 최대 크기를 의미하지 않는다. 이번에 먼저 도달한 것은 시간 예산이며 A2에 이 실측 중단 근거를 제시한다. 입력을 늘린 보충 조건이라는 점은 명확히 구분하며 원래 20,000개 데이터에서도 같은 문제가 발생했다고 주장하지 않는다.

환경은 원자료의 machine에 기록했다. 순차 측정했으며 다른 사용자 앱은 통제하지 않았다. 과제에서 데이터 크기 변경을 명시적으로 금지하지는 않지만, 기본 입력 고정을 요구하는 채점 해석이라면 보충 실험의 인정 여부는 교수님의 판단이다.

[보충 실험 원자료](evidence/a2_boundary.json)

```bash
python task2_boundary.py --baskets 200000 --supports 250,125,62,31,15,7,3,1
python task2_report.py
```

앞선 완료 행은 20만 개 입력에서 `--supports 4000,2000,1000,500,250`로 시작한 별도 실행 기록이다. 위 명령은 중단 후 250부터 확인한 실행의 재현 설정이며 표의 모든 행을 한 번에 새로 측정하는 명령은 아니다.

보충 측정기는 기존 원자료가 있으면 재실행을 거부하므로 먼저 기록을 검토해야 한다. 보고서 갱신은 측정을 다시 실행하지 않는다.
