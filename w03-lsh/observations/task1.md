# Task 1 — MinHash와 LSH 관찰

## 1. 열마다 순회하지 않고 행을 한 번씩 순회하는 이유

행렬의 각 행은 원소를, 각 열은 집합을 나타낸다. MinHash 서명은 해당 집합에 포함된 행들의 해시값 중 최솟값으로 구성된다.

구현에서는 `for r in range(n_rows)`를 가장 바깥쪽 반복문으로 두어 각 행 번호를 한 번씩 방문한다. 현재 행에 각 해시 함수를 한 번씩 적용한 뒤, 그 행을 포함하는 모든 열의 서명을 갱신한다. 따라서 같은 행의 해시값을 열마다 다시 계산하지 않고 재사용한다. 행을 정렬하거나 열마다 전체 행을 다시 순회하지 않는다.

이 방식은 데이터를 메모리에 모두 올릴 수 없는 상황에서 중요하다. 행 단위로 데이터를 읽을 때 현재 행과 누적 서명만 유지하면서 처리할 수 있으며, 열마다 원본 데이터를 다시 읽는 데 드는 입출력 비용을 피할 수 있다. 단, 이번 과제의 함수는 이미 메모리에 있는 열별 집합 `columns`를 입력받는다. 현재 구현 자체가 디스크의 대용량 데이터를 읽는 스트리밍 입출력까지 구현한 것은 아니며, 행 중심의 갱신 방식을 구현한 것이다.

## 2. 서명 길이가 밴드 수로 나누어떨어지지 않을 때의 처리

서명 길이가 밴드 수로 나누어떨어지지 않으면 `ValueError`를 발생시키도록 했다. 예를 들어 서명 길이가 5이고 밴드 수가 2이면 오류로 처리한다.

이렇게 하면 모든 밴드의 크기를 동일하게 유지하고, 나머지 서명 값을 임의로 버리는 일을 방지할 수 있다. 서로 다른 크기의 밴드를 사용하면 밴드별 일치 확률도 달라지므로, 이번 구현에서는 같은 크기의 밴드를 사용하도록 입력을 제한했다. 사용자는 서명 길이의 약수에 해당하는 밴드 수를 선택해야 한다.

추가로 밴드 수가 양의 정수인지, 모든 서명의 길이가 같은지, 서명 길이가 0이 아닌지 확인한다. 입력 서명 목록 자체가 비어 있으면 비교할 대상이 없으므로 빈 후보 집합을 반환한다.

## 3. S1–S4의 추정 오차를 줄이는 방법과 비용

예제에서 S1은 `{0, 3}`, S4는 `{0, 2, 3}`이다. 교집합의 크기는 2이고 합집합의 크기는 3이므로 실제 자카드 유사도는 `2/3`이다.

두 집합의 MinHash 서명은 모두 `[1, 0]`이다. 두 위치가 모두 일치하므로 서명 일치 비율로 추정한 유사도는 `2/2 = 1.0`이다. 해시 함수가 두 개뿐이므로 추정에 사용하는 표본이 적고, 이 예제처럼 실제 유사도와 차이가 날 수 있다.

사용한 해시 함수는 `h1(r) = (r + 1) % 5`와 `h2(r) = (3r + 1) % 5`이다. 각 집합에 포함된 행에 적용하면 다음과 같다. 표의 해시값은 왼쪽의 행 번호 순서대로 나열했다.

| 집합 | 포함된 행 번호 | 첫 번째 해시값 → 최솟값 | 두 번째 해시값 → 최솟값 |
|---|---|---|---|
| S1 | `0, 3` | `1, 4` → **1** | `1, 0` → **0** |
| S4 | `0, 2, 3` | `1, 3, 4` → **1** | `1, 2, 0` → **0** |

S4에만 있는 2번 행의 해시값은 각각 3과 2로, 어느 쪽에서도 기존 최솟값인 1과 0을 바꾸지 않는다. 따라서 원래 집합은 서로 다르지만 두 해시 함수로 만든 서명은 같아진다. 이 예제는 서명이 같다고 해서 원래 집합까지 같다는 뜻은 아니라는 점을 보여준다.

오차를 줄이려면 적절한 MinHash 해시 함수를 더 많이 사용하여 서명을 길게 만든다. 같은 함수를 반복하는 대신, 독립적인 무작위 순열을 근사하는 해시 함수들을 사용하는 것이 중요하다. 이상적인 독립 MinHash 모델에서 실제 유사도를 s, 해시 함수 수를 k라고 하면 추정량의 분산은 `s(1-s)/k`이다. 따라서 함수 수를 늘리면 일반적으로 추정의 변동성이 줄어든다. 다만 특정 실행에서 반드시 실제 값에 더 가까워진다는 뜻은 아니다.

그 대가로 행마다 계산하는 해시값과 서명 갱신 작업이 늘어나며, 집합마다 저장하는 서명의 크기도 증가한다. 해시 함수 수를 k, 집합 수를 C라고 하면 서명 저장 공간은 `O(Ck)`이다. 이상적인 모델에서 표준오차를 절반으로 줄이려면 해시 함수 수가 약 네 배 필요하므로 정확도와 계산·저장 비용 사이의 절충이 필요하다.

LSH는 서명 추정값 자체를 더 정확하게 만드는 단계가 아니라, 비교할 후보 쌍을 줄이는 단계다. 후보 쌍의 정확한 유사도가 필요하면 원래 집합에 자카드 유사도 함수를 적용할 수 있다. 서명 길이를 변경할 때는 밴드 수도 나누어떨어지도록 조정해야 한다.
