## Task 2

[Task 2 개별 observation](../observations/task2.md)

Core i5-11400H, RAM 16 GB급, Python 3.11.9에서 세 크기를 각각 5회 재측정했다. 500개는 전체 비교가 5회 모두 빨랐고 750·1,000개는 LSH가 5회 모두 빨랐다. 이번 조건의 관측 역전 구간은 500~750개이며 정확한 경계나 다른 환경의 결과를 보장하지 않는다.
기존 크기 확장 실험의 시간 배율은 4.49, 4.43, 4.15, 3.98배로 대체로 이차 증가였다. 4,000개에서 59.44초로 과제의 약 1분 대기 기준에 도달해 확장을 종료했으며 메모리 부족은 없었다. 최대 크기 추가 Python 메모리는 전체 비교 22,312 bytes, LSH 29,714,016 bytes다. 2,120개 이후에는 무작위 문서만 추가하여 유사 문서 비율이 일정하지 않다는 한계가 있다. [상세 측정](curve.md).

## Task 3

[Task 3 개별 observation](../observations/task3.md)

n=120, b=30, r=4로 선택했다. 전환 위치 (1/30)^(1/4)=0.4273을 임계 유사도 0.6보다 낮게 두었고, P(0.6)=1-(1-0.6^4)^30=98.45%로 기준 근처 쌍의 누락을 줄이고자 했다. 실측은 119/121개(재현율 98.35%), 비교 132회, 회피율 99.9941%였다.
b=10으로 전환 위치를 0.8254까지 올리자 재현율이 32.23%로 떨어졌다. b=40은 100%를 찾지만 비교가 248회로 증가했다. 해시 계산은 점수에 무료일 뿐이며, 작은 데이터의 준비 비용이나 큰 어휘·긴 문서에서의 O(Vk) 캐시 공간 및 O(Tk) 서명 갱신 비용이 커지면 무시할 수 없다. [수식과 실험](../observations/task3.md).
